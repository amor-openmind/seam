Add a machine

Run one line on the other machine. It fetches the matching version, checks it, and joins this fleet — no downloads to find, no versions to match by hand.

SEAM_SERVER=192.168.2.69:24810 sh -c "$(curl -fsSL http://192.168.2.69:24810/join.sh)"
1
Asks this machine which version to run
The only thing the other machine trusts this one for — a single version number.
2
Downloads that release from GitHub over TLS
Not from here. A binary served off a machine on your network is unauthenticated and unverifiable.
3
Checks it against the release's published checksum
A mismatch refuses to run rather than warning and continuing.
4
Keeps it, and starts
Running the line again on an up-to-date machine starts it rather than downloading anything.

Why not just serve the binary from here? Because then the machine handing out the software would be the one machine nobody verified. The version number is cheap to trust; the bytes are not, so they come from the release page with their checksums.

After it starts

The two machines still have to be introduced — downloading seam is not the same as trusting it.

Both screens will show the same six digits. Confirm they match, and the machines are paired for good.

Every machine must run the same version. Clipboard images and files need matching protocol on both ends, and a machine that is behind closes the link rather than guessing. This command always fetches the version this machine is running, which is what keeps them in step.
