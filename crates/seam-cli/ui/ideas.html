What to build next

Each idea carries what it costs and, where it matters, why the obvious version of it does not work.

The question that was asked

ⓘ
Clients cannot be a web page — but the control panel can
A browser cannot move your cursor or press your keys; that sandbox is the reason browsing is safe at all. Any machine that receives input must run native code. What can travel over a URL is everything about the fleet — which is most of what a person opens seam to look at.
Open the fleet page from any machinemedium
The page is loopback-only today. Serve it on the network as well and every machine — including a phone — can watch the desk, switch machines off, release the pointer and stop seam, without installing anything.
The catch that decides the design: the moment it leaves loopback it needs to authenticate, and a password would be a configuration seam has spent its life avoiding. It already has the answer — the same six-digit confirmation used for pairing, shown on the host machine and typed once per device, then remembered.
Read-only view by defaultsmall
A phone on the sofa should be able to see which machine has the pointer without being able to quit the daemon. Viewing and controlling are different permissions and the page already knows which actions are which.

Making it whole

Windows machines share their own inputlarge
Today only macOS captures; Windows replays. That is why there is no “make this the server” switch — it would be a control that lies. This is the single change that would make the fleet symmetric.
Cost: a low-level keyboard and mouse hook, its own suppression story, and the elevated-window problem all over again on the capture side. Comparable to the entire macOS capture path, which took this project most of its life.
Large clipboard transfers that stream and resumemedium
Copies over 64 MB are refused rather than sent half-finished. Offer, pull, chunk and resume from the receiver's high-water mark — already specified, not built.
The fleet, visible from every machinesmall
A client lists only the machine it paired with, because pairing is pairwise and the fleet is a star. The centre should push its peer list so every machine can show the fleet — display only, never a basis for trust.
Drag a file across the edgelarge
Carry a real drag between machines: pick a file up on one screen, cross the boundary, drop it on another. The clipboard already moves files; this is the gesture people actually reach for.

Fewer surprises

Tests around the screenssmall
Three regressions in a row were features breaking something that already worked: a refactor dropped the origin check, navigation broke the quit button, and closed links were never removed. None had a test.
Worth more than it looks: every one of those shipped, and every one was found by a person rather than by the build.
A signed, notarised macOS buildmedium
macOS ties Accessibility and Input Monitoring to the exact binary, so every update silently loses both and the machine starts mirroring instead of switching. A stable signing identity keeps permissions across updates — removing the most repeated confusion this project has produced.
Say it out loud when a machine falls behindsmall
Mismatched versions close the link rather than guessing, which is correct and invisible. The fleet page knows every machine's version and should say plainly which one needs updating.

Not worth building

A full mesh, every machine paired with every otherdeclined
It would let every machine see every other directly — at the cost of n² confirmations by hand, or transitive trust, which quietly turns one compromised machine into a compromised fleet. Pushing the fleet list from the centre gives the same view without the trade.
Reaching the login and UAC screensblocked
The Windows secure desktop needs a Microsoft-signed UIAccess binary. No KVM reaches it without one, Barrier included. Better stated than quietly broken.
